Advanced DOM and Events Learn More

Section Overview

  • DOM is not part of JS. It is Web API to interact with the HTML document and Browser Events.
  • DOM consists of nodes (elements, attributes, text) and provides methods to manipulate(Create, Update, Delete) them.
  • Events are actions or occurrences that happen in the browser, such as clicks or key presses which is getting from event target.
  • DOM Select Elements: querySelector, querySelectorAll, getElementById, getElementsByClassName, getElementsByTagName
  • Difference between querySelector and getElementsByClassName is that querySelector returns first matching element and getElementsByClassName returns HTMLCollection of all matching elements. Also, querySelector supports foreach loop directly whereas HTMLCollection need to convert into array first to use forEach loop.
  • DOM Create Elements: createElement, insertAdjacentHTML, innerHTML
  • DOM Insert Elements: append, prepend, before, after, cloneNode
  • DOM Delete Elements: remove, innerHTML = ''
  • DOM Update Elements: textContent, innerHTML, setAttribute, style
  • DOM Classes: style property, classList (add, remove, toggle, contains)
  • DOM Styles : style property, getComputedStyle(), setProperty()
  • DOM Attributes: getAttribute, setAttribute, hasAttribute, removeAttribute
  • DOM Window Scroll Properties: scrollX, scrollY, pageXOffset, pageYOffset
  • DOM Window Scroll Methods: scrollTo(), scrollBy(), scrollIntoView()
  • DOM Element Scroll Properties: getBoundingClientRect(). It returns the size and position of an element relative to the viewport.
  • DOM height and Width: clientHeight, clientWidth, scrollHeight, scrollWidth
  • DOM Events: addEventListener, removeEventListener, onmouseenter(old-methods, overriden when we cal other functions) , event propagation(bubbling and capturing), event delegation
  • Capturing Phase: When events are captured and handled by the ancestors of the target element
  • Target Phase: When events are handled by the target element itself
  • Bubbling Phase: When events bubble up and are handled by the ancestors of the target element (from target to root - bottom to top).
  • addEventListener, third parameter false indicates bubbling phase.
  • addEventListener("mouseover") is the opposite of mouseout. mouseover is the preferred eventlistener because it follow bubble event propagation where as mouseenter doesn't.
  • addEventListener("mouseenter") is the opposite of mouseleave.
  • Event Propagation: The process of how events move through the DOM tree (capturing-> target-> bubbling)
  • Event delegation: A technique where a single event listener is added to a parent element to handle events for all its children. main advantage is performance improvement when dealing with many elements.
  • DOM Traversing: It allows navigation through the DOM tree from a selected element to its parents, children, and siblings using properties like parentNode, children.
  • DOM Traversing Children: children, childElementCount, firstChild, lastChild, firstElementChild, lastElementChild
  • DOM Traversing Parents: parentNode, parentElement, closest()
  • DOM Traversing Siblings: previousSibling, nextSibling, previousElementSibling, nextElementSibling
  • Event Passing as arguments: Using bind() method to pass arguments to event handlers
  • Intersection Observer definition: A way to observe when elements intersect with the viewport or other elements
  • Intersection Observer Process: The process of observing elements and triggering callbacks when they intersect with a root element or viewport which meets the threshold value. rootmargin is the margin around the root element.
  • Intersection Observer API: observe(), unobserve(), disconnect()
  • Lazy Loading: A technique to defer loading of images until they are needed
  • DOM Lifecycle Events: DOMContentLoaded, load, beforeunload
  • DOMContentLoaded event is fired when the HTML is completely parsed and DOM tree is built. It does not wait for stylesheets, images, and subframes to finish loading.
  • load event is fired when the whole page has loaded, including all dependent resources such as stylesheets and images.
  • beforeunload event is fired when the window, the document and its resources are about to be unloaded. This event enables you to display a confirmation dialog to the user, asking them if they really want to leave the page.
  • Effeicient script loading methods: Regular(end-of-body) vs async vs defer
  • Regular script loading: Scripts are executed immediately when they are encountered in the HTML document.
  • Async script loading: Scripts are downloaded asynchronously and executed as soon as they are downloaded, without blocking the HTML parsing.
  • Defer script loading: Scripts are downloaded asynchronously and executed after the HTML document is fully parsed, but before the DOMContentLoaded event.
  • Most efficient script loading method: Defer is generally the most efficient for scripts that depend on the DOM being fully loaded. It ensures that the script runs after the HTML is parsed, without blocking the rendering of the page. Also, multiple defer scripts maintain their order of execution.

Object Oriented Programming (OOP) With JavaScript Learn More

Section Overview

  • Object-oriented programming (OOP) is a programming paradigm that uses objects and classes to organize code.
  • 4 Fundamental OOP Concepts: Encapsulation, Abstraction, Inheritance, Polymorphism
  • Encapsulation is the practice of keeping fields within a class private, then providing access to them via public methods.
  • Abstraction is the concept of hiding the complex implementation details and showing only the necessary features of an object.
  • Inheritance is a mechanism that allows a new class (subclass) to inherit properties and methods from an existing class (superclass).
  • Polymorphism is the ability of different classes to be treated as instances of the same class through inheritance, typically by overriding methods.
  • JavaScript is a prototype-based language, not a class-based one. prototypes actually means "to first show" which is a mechanism by which an object can inherit properties and methods from another object.
  • Every object has a prototype, and the prototype itself is an object, which can have its own prototype, forming a chain.
  • Prototype chain: Objects can inherit from other objects, forming a chain of prototypes.
  • Prototype Inheritance allows objects to inherit properties and methods from other objects.
  • 3 ways to implement Prototype inheritance in javascript: Constructor functions, ES6 Classes, Object.create()
  • Constructor functions:
    • Constructor functions are used to create and initialize objects in JavaScript. This is how in-built objects like Array, Date, and others are created.
    • Inheritance between constructor functions is achieved using the prototype property.
  • ES6 Classes:
    • ES6 classes are syntactic sugar over constructor functions. It means that classes are just a different way of writing constructor functions. However it is not similar to classes in other programming languages like Java, C++ etc as JavaScript still uses prototype-based inheritance under the hood even when using ES6 classes whereas other programming languages use class-based inheritance.
    • They provide a more concise and readable way to create objects and implement inheritance.
    • Inheritance between ES6 classes is achieved using the `extends` keyword and `super()` function.
  • Object.create():
    • The Object.create() method creates a new object, using an existing object as the prototype of the newly created object.
    • It allows us to create objects that inherit properties and methods from another object, without the need for constructor functions or classes.
    • Inheritance using Object.create() is achieved by creating a new object that inherits from the prototype of the superclass.

Asynchronous JavaScript Learn More

Section Overview

  • Asynchronous JavaScript allows us to perform tasks that take time to complete without blocking the main thread, enabling a responsive user experience.
  • AJAX (Asynchronous JavaScript and XML) is a technique for making asynchronous HTTP requests to retrieve data from a server without refreshing the page.
  • API (Application Programming Interface) is a set of rules and protocols that allows different software applications to communicate with each other.
  • The XMLHttpRequest object is used to make AJAX requests and handle responses from the server, allowing us to update parts of a web page without reloading the entire page.
  • When we access a server, several steps occur behind the scenes, including DNS resolution, sending an HTTP request, receiving an HTTP response, and rendering the content on the page. This process is handled asynchronously to ensure a smooth user experience.
  • We can handle asynchronous operations using callbacks, Promises, or async/await, each with its own advantages and use cases.
  • The JavaScript runtime environment uses an event loop to manage the execution of code and handle asynchronous operations, ensuring that the main thread remains responsive.
  • Callbacks are functions passed as arguments to other functions, often used in asynchronous operations. But callback hell can make code hard to read and maintain.
  • Promises provide a more elegant way to handle asynchronous operations and avoid callback hell. They have a lifecycle of pending, fulfilled, or rejected. While consuming Promises, we can use .then() and .catch() methods to handle the fulfillment or rejection of a Promise. whereas creating a Promise involves defining an executor function that contains the asynchronous operation and uses resolve and reject to indicate success or failure.
  • Promise using async/await syntax will write cleaner and more readable asynchronous code. It allows us to write asynchronous code that looks synchronous and is easier to understand and maintain.
  • Promise.all, Promise.race, Promise.allSettled, and Promise.any are methods that allow us to handle multiple Promises together, each with its own behavior for resolving or rejecting based on the input Promises.

JavaScript Modules and Tooling Learn More

Section Overview

  • JavaScript modules are reusable pieces of code that can be imported and exported between different files in a JavaScript application.
  • Modules help organize code, avoid naming conflicts, and make code more maintainable and reusable.
  • The build process involves compiling, minifying, and optimizing JavaScript code for production use.
  • NPM is a tool that allows developers to manage and share JavaScript packages.
  • Webpack and Parcel are popular build tools that help automate and optimize JavaScript development workflows.
  • ES6 introduced a standardized module system that allows developers to define and use modules in a consistent way across different JavaScript environments.
  • Importing creates a live connection to the exported value. So if the value changes in the exporting module, the imported value also changes.
  • Top-level await allows us to use the await keyword outside of an async function, at the top level of a module.
  • The module pattern is a design pattern that allows us to create modules in JavaScript using an IIFE (Immediately Invoked Function Expression).
  • CommonJS is a module system used in Node.js that allows developers to create and use modules in a way that is similar to ES6 modules, but with some differences in syntax and behavior.
  • AMD (Asynchronous Module Definition) is a module system that allows developers to define and use modules in a way that is optimized for asynchronous loading in the browser.
  • Basic terminal commands include ls (list files), cd (change directory), mkdir (make directory), rm (remove files), and touch (create a new file).
  • NPM allows you to manage dependencies for your project, ensuring that all required packages are installed and up to date.
  • Babel is a JavaScript transpiler that allows developers to write modern JavaScript code and have it transpiled into a version of JavaScript that is compatible with older browsers and environments.
  • Best practices for modern and clean code include using meaningful variable and function names, keeping functions small and focused, avoiding global variables, and using comments to explain complex code.
  • Imperative programming focuses on describing how a program should achieve a specific task, while declarative programming focuses on describing what a program should accomplish rather than how it should achieve it.
  • Declarative programming aims to minimize side effects, emphasizes immutability and pure functions, and often makes use of array and object destructuring, template literals, arrow functions, and the spread operator.

  • Users can also add their own recipes to the app, which are stored in local storage for persistence across sessions.

  • MVC Architecture
    • MVC (Model-View-Controller) is a software architectural pattern that separates an application into three main components: Model, View, and Controller.
    • Why we use need architechture:
      1. Organization: It provides a clear structure for organizing code and separating concerns.
      2. Maintainability: It makes it easier to maintain and update the codebase by isolating different parts of the application.
      3. Reusability: It allows for the reuse of components across different parts of the application.
    • Definition:
      1. Model: Manages the data and business logic of the application.
      2. View: Handles the presentation and user interface of the application.
      3. Controller: Acts as an intermediary between the Model and View, handling user input and updating the Model and View accordingly.
    • Components of Architechture:
      1. Business Logic: Handles the core functionality and rules of the application.
      2. State Management: Manages the state of the application, including data and user interactions.
      3. HTTP Requests: Manages the communication with external APIs and servers.
      4. Application Logic: Handles the overall flow and coordination of the application.
      5. Presentation: Manages the user interface and user experience aspects of the application.
  • MVC Event Handlers: Publisher - Subscriber Pattern
    • Publisher - Subscriber Pattern is a design pattern that allows components to communicate with each other without being tightly coupled. In this pattern, the publisher component emits events, and the subscriber component listens for those events and reacts accordingly.
    • In the context of the Forkify app, the Controller acts as the publisher, emitting events when user interactions occur (e.g., searching for a recipe, bookmarking a recipe). The Model and View act as subscribers, listening for these events and updating the application state and user interface accordingly.
  • JSDOC Comments:
    • JSDoc is a documentation generator for JavaScript that allows developers to add comments to their code in a standardized format.
    • It helps improve code readability and maintainability by providing clear documentation for functions, methods, and other code elements
